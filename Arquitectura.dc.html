Tecnología por capa y por qué

  • Cliente: Blade + JavaScript sin framework. Laravel pinta las páginas, que cargan rápido y Google las indexa. JavaScript añade lo interactivo (filtros, compra, validaciones, lector de QR) pidiendo los datos a la API. Se descarta React: la web tiene pocas pantallas y añadiría compilación y peso.
  • API: rutas /api/v1 en Laravel. JSON con códigos HTTP coherentes. La usan la web pública, el portero y el panel.
  • Servidor: PHP 8.3 + Laravel 11. Trae autenticación, validación, colas, correo, tareas programadas y migraciones. Es lo que se trabaja en el ciclo.
  • Base de datos: MySQL 8. Datos relacionales y transacciones para no vender por encima del aforo.
  • Pago: Stripe Checkout. La tarjeta nunca pasa por el servidor del pub. Se descarta Stripe Elements por complejidad.
  • Panel admin propio con Blade. Se descarta Filament para que el trabajo sea propio y demostrable.
  • Cola en la base de datos. Se descarta Redis: un servicio más que el volumen del pub no necesita.
  • PDF: laravel-dompdf. Un PDF por compra con un QR por entrada, adjunto al correo, y la lista de la puerta para el plan B.
  • QR: html5-qrcode para leer, simple-qrcode para generar. Funciona en Android e iPhone. La API nativa del navegador no está en todos los móviles.
  • Despliegue: Hetzner CX23. Unos 6 € al mes, pago por horas sin permanencia, centro de datos en la UE (RGPD) y control total del servidor.

Flujo de una compra

  1. El comprador elige las entradas y deja nombre, email y teléfono.
  2. POST /api/v1/compras: CompraService crea la compra pendiente y reserva el stock 10 minutos en una transacción.
  3. Laravel pide a Stripe una sesión de pago y el navegador va a la página de Stripe.
  4. Stripe avisa con un webhook: la compra pasa a pagada y se crean las entradas con su código QR.
  5. Se genera el PDF con un QR por entrada (laravel-dompdf) y se pone en cola el correo con el PDF adjunto. Supervisor lo envía y queda registrado en notificaciones.
  6. En la puerta, el portero escanea el QR: POST /api/v1/acceso/validar la marca como usada.
  7. Si no se paga en 10 minutos, el cron cancela la compra y libera el stock.

Entornos

  • Desarrollo: Docker con Laravel Sail en casa (Windows con WSL2) y en clase (Linux). Mismas versiones que en producción.
  • Código: se sincroniza con GitHub. Pull al empezar, commit y push al terminar.
  • Datos: no se copian entre ordenadores. Se crean con migraciones y seeders con datos ficticios.
  • Secretos: el archivo .env no se sube a Git. Cada entorno tiene el suyo a partir de .env.example.
  • Producción: Hetzner CX23 con Nginx, PHP-FPM, MySQL, Supervisor y cron en la misma máquina.
